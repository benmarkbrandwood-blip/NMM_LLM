## 3. Gaps and risks the GapNet v3 plan MUST address (things Claude should not skip past)

1. **Regret has no operational definition yet.** The human_blunder_net_plan explicitly punts this to "the GapNet plan." GapNet v3 is that plan — it cannot cite `malom_regret(m)` as if it already exists. It must **define and version** one of: (a) P(non-oracle move), (b) ordinal rank loss, (c) frozen W/D/L utility + within-class distance, and **fail closed** (missing Malom lookup ≠ regret 0).
2. **HumanBlunderNet is unevaluated at scale.** Per rev-4 of the plan, Phase 3 code is done but the note in `retrain_v2_plan.md` says the *last full eval run happened for HumanPrefNet, not HumanBlunderNet*. GapNet v3 should not assume HumanBlunderNet's calibration is good — treat its Phase-4 eval (event-weighted NLL, ECE, per-band, per-transition) as a **prerequisite gate**, not a given.
3. **HumanPrefNet's Spearman r=0.191 failed its own bar (≥0.5).** If GapNet v3 leans on HumanPrefNet's ranking signal at all (it's the "human pref net" mentioned in the query), that weakness should be flagged — top-1/top-3 accuracy is fine but rank-order fidelity is weak, which matters if any part of the design wants relative ordering rather than just top-1 identity.
4. **Candidate DB not activated.** `data/human_db_candidate.sqlite` (v3, with Elo bins) exists but isn't live. GapNet v3 training data extraction depends on this candidate DB (or its activation). The plan should state explicitly whether it trains against the *candidate* or requires activation first (activation is described in existing docs as a deliberate, backed-up, manual step — don't have Claude silently assume it's done).
5. **Sparse support at the position level.** Phase-1 audit shows only ~4% of distinct positions have ≥5 plays in any Elo band. A "gap net v3" that computes per-position regret × human-probability at inference time will mostly be evaluating on **unseen** positions — meaning it depends entirely on the *networks'* generalization, not on lookup tables. The plan needs a story for out-of-training-distribution positions (this is arguably the single biggest technical risk).
6. **Confound: is GapNet v2's existing "opportunity gap" signal now redundant with expected-regret?** GapNet v1/v2 already computes something similar (`malom_top_q − weighted human quality`) via `build_gap_dataset.py`'s `y_hp` aux label. V3 should clarify: is it a full retrain, a distillation/blend of the old target with the new HumanBlunderNet-derived expected-regret, or a completely separate net? The plan needs to be explicit about **relationship to gap_net.npz / gap_net_v2.npz naming** so it doesn't silently clobber the currently-deployed GapNet used in live play (`web/app.py` loads `data/gap_net.npz` directly).
7. **Asymmetric application today; symmetric application implied by the new ask.** Current GapNet correction is applied only at the AI's own leaf nodes (`_negamax` depth==0, exclusive to AI side) per `AI_INTERNALS.md`. But the new prompt wants to use this signal for BOTH (a) in-game play (presumably to *predict where the opponent human will falter*, i.e. applied to the **opponent's** side of the tree) and (b) a training signal for gen 3 self-play. That's a different application point than today's code — Claude should design for dual-consumption (inference-time opponent-side signal + training-time reward shaping) rather than reusing the exact same asymmetric hook.
8. **Elo-band conditioning is corpus-relative, not absolute.** The whole PlayOK corpus tops out at p95=1400 Elo — "lower/middle/upper" are relative bands within amateur play, not a universal skill scale. If GapNet v3 is meant to generalize to arbitrary opponents (including strong players or the difficulty-1-10 AI itself), the plan must decide how band selection happens at inference (e.g., estimated from `PlayerProfile`/`player_profile.py`, or defaulted to "middle").
9. **Test discipline precedent.** Every phase of the blunder-net work has landed with dedicated regression tests (perspective-flip tests, softmax-denominator tests, provenance tests). GapNet v3's plan should specify equivalent test categories up front (e.g., "regret never silently defaults to 0," "expected-regret formula uses every legal move," "training and eval share one regret-version constant") rather than leaving this to be caught in review.

## 4. External research context (useful analogues Claude should weigh)

- **Regret is not simply "value gap."** In counterfactual regret minimization (CFR) literature, regret at an infoset is the difference between realized utility and the best achievable utility in hindsight, accumulated over iterations — not a raw scalar subtraction of two point-values from an oracle. This directly supports the repo's own caution about not doing raw `key2` subtraction against Malom values, and suggests versioned, explicitly-defined utility mappings (as the plan already proposes) rather than ad hoc deltas [web:19][web:23].
- **Maia (chess, KDD 2020)** trained an AlphaZero-style network purely to *predict human moves at specific skill levels* (not to play well) by training separate models per Elo bracket from Lichess games — directly analogous to HumanBlunderNet's Elo-banded softmax approach, and empirical validation that skill-conditioned move-prediction nets generalize meaningfully across bands [web:12].
- **Chess blunder prediction research (Ben-Gurion Univ., 2026)** shows a hybrid DeepFM-style architecture (frozen board-CNN embeddings + learned per-player embeddings) achieves 0.801 AUC predicting blunders, and importantly finds the learned "blunder profile" embedding is a **stronger predictor than raw Elo** — suggesting that if GapNet v3 wants sharper regret-risk detection than Elo-band alone provides, a low-dimensional player-style embedding (extending `ai/player_profile.py`) could outperform static Elo bands, at the cost of needing per-player history [web:21].
- **"Assessing Human Error Against a Benchmark of Perfection" (Toronto, chess).** Found the *difficulty of the position itself* dominates blunder prediction more than either player skill or time — decision-tree models using "blunder potential" features alone hit 73% accuracy vs 54% for Elo-only. This strongly supports coupling GapNet v3's regret signal to **position-complexity features** (e.g., number of near-equal-value legal moves, branching factor of traps) in addition to Elo band [web:18].
- **CrazyAra (Crazyhouse, 2020)** demonstrates strong move-prediction (60.4% top-1) purely supervised on human games without RL, useful precedent that a well-tuned supervised human-move predictor (i.e., HumanBlunderNet) can be trusted as a standalone signal without further RL fine-tuning, if data volume and calibration are adequate [web:22].
- **Deep CFR + opponent modeling (ODCFR, 2025)** — recent work explicitly blends a learned opponent model into a CFR-style regret-minimization loop; relevant if gen-3 training wants the GapNet-style human-fallibility signal to shape the *training* reward (not just inference), since ODCFR-style approaches show opponent-aware regret estimation improves both exploitability and sample efficiency versus regret computed against a self-play-only baseline [web:9].

## 5. Suggested framing for the "gap_net_v3_plan.md" itself (for Claude to structure around)

1. **Definitions section first**: lock down "regret" (versioned formula + fail-closed behavior) before anything else — this removes the single largest blocker flagged by the existing docs.
2. **Two consumption modes, one signal**: (a) inference-time — bias search/heuristic toward positions/moves where the *opponent* (assumed human, Elo-banded or profile-embedded) has high expected regret, i.e., steering toward "opponent traps," and (b) training-time — reward-shaping term or auxiliary loss for gen-3 self-play, replacing or supplementing the current `gap_blend_place`/`gap_blend_move` heuristic caps.
3. **Naming/versioning discipline**: explicit target filenames (don't silently overwrite `data/gap_net.npz` used in live play — mirror the `human_db_candidate.sqlite` pattern with a `gap_net_v3_candidate.npz` until validated).
4. **Dependency gate order**: HumanBlunderNet Phase 4 eval must show acceptable calibration (event NLL, ECE, per-band) *before* GapNet v3 consumes it as ground truth for "where humans will falter" — otherwise v3 inherits an unvalidated upstream signal.
5. **Position-complexity features** as a candidate input alongside Elo band, per the difficulty-dominates-blunders research above — worth at least scoping even if deferred.
6. **Test plan mirroring existing precedent**: perspective-consistency tests, "every legal move in denominator" tests, regret-never-defaults-to-zero tests, train/eval regret-version-match tests.
7. **Explicit non-goals section** (repo convention) — e.g., not retraining ValueNet, not touching the active `human_db.sqlite`, not activating the v3 candidate DB without a separate sign-off step.
